# 封禁状态流转

## 1. 状态枚举（BanStatus）

| 枚举值 | 含义 | 是否计入 validBanCount |
|--------|------|:---:|
| `ACTIVE` | 生效封禁（正在封禁中） | —（封禁时计入） |
| `EXPIRED` | 到期自动解除 | ✅ 计入 |
| `FALSE_POSITIVE` | 管理员标记误封解除 | ❌ 不计入（不叠加次数） |
| `MANUAL_UNBAN` | 管理员普通解除 | 由配置 `punishment.manualUnbanCounts` 决定（默认不计） |

## 3. 处罚阶梯（核心规则）

以 **UUID 为主键**，维护每位玩家的 `validBanCount`（有效封禁次数，只用于阶梯判定）。

```
触发自动封禁时：
    读取该 UUID 的 validBanCount
    validBanCount == 0  → 创建 15 天限时封禁，validBanCount += 1
    validBanCount >= 1  → 创建永久封禁
```

- **首次有效封禁**：15 天限时。
- **第二次有效封禁**：永久。
- 关键：只有 **有效封禁**（ACTIVE 及其到期的 EXPIRED）才计入阶梯；
  **误封（FALSE_POSITIVE）不计入**，因此误封不会导致玩家下次直接被永久封禁。

## 4. 计数变化明细

| 操作 | validBanCount 变化 |
|------|:---:|
| 自动封禁（首次） | +1 |
| 自动封禁（二次及以上） | +1（同时触发永久） |
| 到期自动解除（→ EXPIRED） | 不变（封禁时已计入） |
| `unban <uuid> falsepositive`（→ FALSE_POSITIVE） | **-1 回退**（不叠加） |
| `unban <uuid>`（→ MANUAL_UNBAN） | `manualUnbanCounts=true` 时不变；`false`（默认）时 **-1 回退** |
| `clearcount <uuid>` | 归零（兜底运维） |

> 说明：解除时对 validBanCount 做 **-1 回退**，是为了保证"误封不叠加次数"的语义成立——
> 若玩家仅有一次误封记录，回退后计数归 0，下次触发仍是 15 天而非永久。

## 5. 到期自动解除

`isActiveBanned(uuid)` 每次查询时顺带检查：
- 若某条 `ACTIVE` 记录非永久且 `now >= banEndMs` → 置为 `EXPIRED`（计入计数）并持久化。
- 玩家在线时到期，由 JOIN 检查与 tick 轮询共同保证最迟下一次加入时解除。

## 6. 设计权衡

- **误封不叠加**：FALSE_POSITIVE 是反作弊对误判的"纠错机制"，绝不能让它把玩家推向永久封禁。
- **MANUAL_UNBAN 可配置计数**：某些服主希望"被人工解封过"也算一次记录（用于留痕），故暴露开关。
- **clearcount 兜底**：用于纠正计数异常（如迁移、误操作），不影响历史记录，仅归零阶梯依据。
