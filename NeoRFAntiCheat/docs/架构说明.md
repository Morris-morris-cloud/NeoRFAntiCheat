# 架构说明

NeoRFAntiCheat 是一个 **纯服务端（environment = "server"）** 的 Fabric 反作弊模组。
所有检测均基于服务端的数据包监听 / 事件监听，**不依赖客户端上报任何数据**
（唯一例外是 `/report` 强制查端会向客户端发送请求，但检测本身独立）。

## 1. 模块总览

## 2. 目录 ↔ 职责对照

| 目录/类 | 职责 |
|--------|------|
| `NeoRFAntiCheat` | 模组入口，初始化各管理器，注册事件与指令 |
| `config/AcConfig` | 配置 POJO，与 JSON 一一对应，含默认值 |
| `config/ConfigManager` | 配置加载 / 保存 / 热重载（/NeoRF reload） |
| `core/tick` | 玩家 tick 数据管理器（位置历史帧、可疑状态计时、违规点登记） |
| `core/snapshot` | 证据快照构造器（坐标、tick、ping、动作数据） |
| `core/threshold` | TPS 自适应阈值管理器（MSPT 过高自动放宽） |
| `core/exemption` | 豁免/白名单（UUID、权限节点、区域） |
| `check/*` | 10 项检测（movement/combat/action/packet） |
| `punishment/*` | 封禁 CRUD、阶梯计数、状态流转 |
| `report/*` | /report 举报、冷却缓存、强制查端 payload |
| `command/*` | /NeoRF 根指令 + 5 子指令 + /report |
| `storage/*` | 持久化抽象（默认 JSON，可切 H2） |
| `util/*` | 数学 / 玩家 / 时间 / 发包工具 |

## 3. 数据流

### 3.1 检测 → 封禁主链路

```
服务端 tick / Fabric 事件
        │
        ▼
Check 检测逻辑 ──判定违规──▶ Check.flag(player, amount, detail)
        │                          │
        │                          ├─ 豁免判定（UUID/权限/区域）→ 命中即跳过
        │                          ▼
        │                 累计违规点 violations
        │                          │
        │                    达到阈值 violationsToBan？
        │                          ▼ 是
        │              SnapshotBuilder 构造证据快照
        │                          ▼
        │              BanManager.applyAutomaticBan
        │                 ├─ 读 validBanCount 走阶梯
        │                 ├─ 写封禁记录（状态=ACTIVE）
        │                 ├─ validBanCount += 1
        │                 ├─ 持久化到 JsonStorage
        │                 └─ 断开玩家连接（踢出）
```

### 3.2 /report 强制查端链路

```
玩家执行 /report <target> [remark]
        │
        ▼
ReportManager.submitReport
   ├─ 校验举报人全局冷却（内存，5 分钟，重启清空）→ 冷却中拒绝
   ├─ 入库举报记录（PENDING）
   ├─ 设置举报人冷却截止时间
   └─ 强制查端：发送 Fabric 自定义 Payload（请求 ModList）
            │
            ├─ 收到 ModList → 提取 modId → 与黑名单比对
            │     ├─ 命中 → BanManager.applyAutomaticBan（阶梯封禁）
            │     └─ 未命中 → 标记"未检出违规模组"，归档待复核
            ├─ 超时（默认 5s）→ 标记 TIMEOUT，归档
            └─ 客户端拒绝/不支持 Fabric payload（原版无 Fabric）→ 标记 NON_FABRIC
```

## 4. 事件注册（Fabric API）

| 事件 | 用途 |
|------|------|
| `ServerLifecycleEvents.SERVER_STARTED` | 加载封禁数据、启动采样、注册 payload |
| `ServerLifecycleEvents.SERVER_STOPPING` | 持久化、关闭资源 |
| `ServerPlayConnectionEvents.JOIN` | 初始化 tick 数据、生效封禁则断开 |
| `ServerPlayConnectionEvents.DISCONNECT` | 清理 tick 数据 |
| `ServerTickEvents.END_SERVER_TICK` | TPS 采样 + 检测循环 |
| `AttackEntityCallback` | 战斗类检测（KillAura/Reach/Aim） |
| `PlayerBlockBreakEvents.AFTER` | Nuker 检测 |
| `UseBlockCallback` | AutoInteract 检测 |
| `ServerPlayNetworking` | 强制查端 payload 收发 |

## 5. 关键设计决策

1. **纯服务端判定**：所有检测服务端独立完成，不信任客户端上报，从根上杜绝"客户端改数据骗过检测"。
2. **违规点累计制**：单次违规不直接封禁，累计到阈值才触发，显著降低误封。
3. **证据快照**：每次封禁固化坐标/时间/ping/动作现场，供误封复核。
4. **TPS 自适应**：MSPT 高时自动放大阈值，TPS 过低跳过时序敏感检测，规避卡顿误判。
5. **三层豁免**：UUID / 权限节点 / 区域白名单，满足主城等场景。
6. **存储抽象**：StorageProvider 接口，默认 JSON 原子写入，可平滑切 H2。
